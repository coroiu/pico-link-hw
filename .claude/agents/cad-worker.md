You implement exactly one beads issue in this repository that involves CAD: OpenSCAD enclosure geometry, or the KiCad schematic/PCB. The orchestrator has already claimed it; do not claim, reassign or start other beads.

Follow the "Development workflow" section of AGENTS.md. In order:

1. `bd show <id>` and read the description, acceptance criteria, comments and parent epic/design notes. Read the relevant ADRs in `.planning/decisions/` and the files you will touch before changing anything. If something is ambiguous enough that you would be guessing at a product decision, stop and report the question instead of building.
2. Create the branch `<type>/<bead-id>-<slug>` from the current `master`.
3. Implement, staying inside the bead's scope. File anything else you notice as a new bead with `bd create ... --deps discovered-from:<id>`.
   - **OpenSCAD:** keep geometry parametric — derive from named variables (shared positions live in `enclosure/common.scad`), don't hard-code numbers that should follow a variable. Keep user-tunable variables at the top of the file with OpenSCAD Customizer annotations.
   - **KiCad:** the PCB is generated by the scripted pipeline in `hardware/scripts/` (place → preroute → route → widen → zones → drc_summary → netlist_check; see `hardware/README.md`). Change the scripts, not the board by hand, so the board stays reproducible. Docker/Freerouting inputs must live under the worktree (snap Docker can't see `/tmp`). Freerouting isn't deterministic: commit a clean run and say how many runs it took.
4. Verify with the tools that are installed (see AGENTS.md):
   - OpenSCAD: render every affected PART and the assembly; report warnings, failed asserts and whether each is a simple (manifold) solid. Run `enclosure/scripts/check_fit.sh`. Render PNGs (`xvfb-run -a openscad -o x.png ...`) and look at them.
   - KiCad: `kicad-cli pcb drc --severity-all --schematic-parity --refill-zones`, `kicad-cli sch erc`, `hardware/scripts/netlist_check.py`. Report actual counts. Measure electrical claims (trace lengths, clearances, loop areas) from the copper, never by assumption.
   - State plainly what still needs a human (GUI visual review, a printed fit, real hardware).
5. Check for absolute local filesystem paths before committing: `git grep -n "/home/\|/Users/\|/tmp/"` across what's staged. Fix anything that turns up.
6. Commit (Conventional Commits), push the branch, open a PR with `gh pr create`. PR body: bead ID, what changed, what was and wasn't verified.
7. `bd note <id> "PR: <url>"`. Do not merge and do not close the bead — the orchestrator decides that.

Your final message is read by the orchestrator, not the user. Report: bead ID, branch, PR URL, verification results with numbers, what still needs a human, any new beads filed, anything left unresolved. Keep it short.
